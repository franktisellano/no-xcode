# iOS without Xcode

The Xcode GUI is never needed. Every step (create the project, build, run on the simulator, run on a phone, test, screenshot, archive, TestFlight) is a terminal command, so an agent can drive the whole loop and *look at its own work* through screenshots.

## Core rules

1. **`project.yml` is the source of truth.** The `.xcodeproj` is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) and is disposable. Never edit `.pbxproj` by hand; change `project.yml` and run `make gen`. Adding a Swift file under a source folder needs no project change, just regenerate.
2. **Everything goes through `make`.** The Makefile is the interface for humans, agents and CI. When you add a new workflow (a new test subset, a deploy step), add a target rather than leaving a long command in someone's notes.
3. **Verify UI by looking.** After a UI change, run the app on the simulator, take a screenshot, and Read the PNG. Do not claim a UI change works until you have seen it.
4. **Test mode is DEBUG-only.** The app reads an env var (`APP_TEST_MODE=1`) at launch to swap in seeded in-memory data and stubbed services. Wrap all of it in `#if DEBUG` so it can never ship.
5. **Keep build output small.** `tools/xcb.sh` wraps `xcodebuild`, writes the full log to `build/xcodebuild.log`, and prints only errors, signing warnings, test failures and the result line. Read the log file only when the summary isn't enough.
6. **Never deploy to a device you weren't asked to.** Device targets need `DEVICE_NAME` when more than one phone is paired.

## Requirements

- Xcode (command-line use only) with an iOS simulator runtime: `xcodebuild -version`, `xcrun simctl list runtimes`
- XcodeGen: `brew install xcodegen`
- For devices and TestFlight: an Apple Developer team. Find team IDs with `tools/find-team.sh`.

## Starting a new app

```bash
<skill-dir>/scripts/scaffold.sh ~/dev/myapp --name MyApp --bundle-id com.example.myapp [--team ABCDE12345] [--display "My App"]
cd ~/dev/myapp && make test && make run && make screenshot
```

The scaffold writes a working SwiftUI app plus unit tests (Swift Testing), UI tests (XCUITest page objects and a screenshot tour), the Makefile, `tools/`, xcconfig secrets plumbing, a GitHub Actions workflow, and an `AGENTS.md` (with a `CLAUDE.md` that imports it) describing the loop. If `--team` is omitted and exactly one signing team is in the keychain, that team is used.

`<skill-dir>` is the directory this SKILL.md lives in.

## Converting an existing Xcode project

1. Read the existing project's targets, build settings, Info.plist, entitlements and package dependencies (`xcodebuild -list`, `xcodebuild -showBuildSettings -scheme X`, the plist and entitlements files).
2. Write an equivalent `project.yml` (see `references/project-yml.md`). Move non-secret build settings into it; move secrets into a gitignored `Secrets.xcconfig`.
3. Copy `templates/Makefile`, `templates/tools/`, `templates/gitignore` → `.gitignore`, and replace `__APP__`, `__BUNDLE_ID__` in them.
4. `make gen && make build`, fix differences, then delete the old hand-made `.xcodeproj` from git (it is now generated and ignored).

## The loop

| Command | What it does |
| --- | --- |
| `make gen` | Regenerate the `.xcodeproj` from `project.yml` |
| `make build` | Simulator build (fast compile check) |
| `make test` | Unit tests on the simulator |
| `make run` | Boot simulator, build, install, launch in test mode |
| `make run-real` | Same, but without test mode (real data path) |
| `make screenshot` | Screenshot the simulator to `build/screenshot.png` |
| `make ui-test` | Run the XCUITest suite → `build/ui.xcresult` |
| `make screenshots` | UI suite, then export every named screenshot to `build/screenshots/` |
| `make tour` | Only the screenshot tour (`Tour-NN-*.png`) |
| `make logs-sim` | Stream the app's log output from the simulator |
| `make device-run` | Signed debug build → install → launch on a paired iPhone |
| `make device-logs` | Launch on the phone with its console attached |
| `make archive` | Release archive (signing sanity check, no upload) |
| `make testflight` | Bump build number, archive, export, upload (needs `.asc.env`) |
| `make devices` / `make sims` | List paired phones / available simulators |
| `make clean` | Remove `build/` and the generated project |

Overrides: `make SIM="iPhone 16" run`, `make APPEARANCE=dark run`, `make DEVICE_NAME="Jane's iPhone" device-run`.

### UI change workflow

1. Edit SwiftUI code. Give every control a test needs a stable `.accessibilityIdentifier("kebab-case-id")`, on the tappable element itself, not a wrapping container.
2. `make run && make screenshot`, then Read `build/screenshot.png`. Check dark mode with `make APPEARANCE=dark run`.
3. To reach screens deeper than the launch screen, add a step to the tour in `UITests/ScreenshotTourTests.swift` (`snapshot(app, named: "Tour-NN-Name")`) and run `make tour`, then Read the PNGs in `build/screenshots/`.
4. For behavior, add assertions in a UI test using the page objects in `UITests/Screens.swift`.

### Logic change workflow

Write or update Swift Testing tests in `<App>Tests/`, run `make test`. Keep domain logic in plain Swift types so it is testable without UI.
